# 🤖 CLAUDE.md — System Instructions for Wanda Team Skills

Цей репозиторій є централізованою базой знань, скілів та правил для команди **Wanda**. 
Він використовується для синхронізації стандартів дизайну, токенів та системних правил між усіма членами команди та ШІ-агентами.

---

## 📌 Rules for Claude / AI Assistant

Коли ви працюєте над завданнями у цьому контексті або звертаєтеся до цього репозиторію, **обов'язково дотримуйтесь наступних правил**:

1. **Завжди перевіряй контекст:** Перед вивантаженням рішень, коду чи токенів звертайся до актуальних правил у цьому репозиторії.
2. **Першоджерело правил:** Правила дизайн-системи знаходяться у папочці `/wanda-design-system/`.
3. **Мова спілкування:** Спілкуйся з командою українською мовою, якщо не вказано інше.
4. **Консистентність:** Не вигадуй власні назви токенів чи стилів, якщо вони вже визначені в правилах дизайн-системи.

## 🎨 Wanda Design System Overview

Головні правила системи знаходяться у `wanda-design-system/rules.md`.

При генерації компонентів, структур чи порад щодо UI/UX обов'язково опирайся на розділи з `rules.md`:
* **Naming Conventions:** Суворе дотримання назв шарів, компонентів та токенів.
* **Layout & Spacing:** Використання системної сітки та кроків відступів (Spacing scale).
* **Color System & Tokens:** Використання семантичних токенів замість «сирих» hex-кодів.
* **Component States:** Обов'язкове врахування всіх станів (Default, Hover, Active, Disabled, Focus).

## 🔄 Team Sync & Contribution Protocol (Для дизайнерів команди)

Щоб зміни в правилах були синхронізовані між усіма членами команди:
1. **Зміни через PR:** Будь-які оновлення в `rules.md` або нові скіли додаються через створення окремої гілки та Pull Request (PR).
2. **Review:** Зміни в дизайн-системі затверджуються відповідальним дизайнером (Lead / Design System Owner).
3. **Commit Messages:** Використовуйте зрозумілий формат коммітів:
   * `feat(rules): add new button states`
   * `fix(tokens): update semantic color naming`
   * `docs(skills): update figma mcp workflow`
