# Wanda — правила роботи з Figma

## 1. Брейкпоінти (xs/sm/md/lg/xl) — збірка/розкладка

1. Горизонтальна відстань між сусідніми фреймами брейкпоінтів — завжди рівно **200px**.
2. Коли рядок/грід (напр. Stats row, Cards) переводиться на `layoutWrap="WRAP"` для рефлоу під вужчі брейкпоінти — обов'язково задавати `counterAxisSpacing` рівним `itemSpacing` (гепу між колонками), інакше рядки, що переносяться, злипаються без відступу по вертикалі.

## 2. Генерація/додавання НОВОГО контенту в лейаути

1. **Компоненти** — використовувати ВИКЛЮЧНО компоненти з дизайн-системи (instance реальних компонентів через `getMainComponentAsync` / `importComponentSetByKeyAsync` / `search_design_system`) — не малювати імітації вручну через fills/rectangles.
2. **Кольори** — тільки токени/змінні дизайн-системи, не хардкодити нові hex-кольори (в т.ч. не використовувати чорний `#000000`/near-black для нових карток/блоків, якщо це не існуючий токен).
3. **Шрифти** — тільки ті, що вже задані в ДС (Bungee для заголовків, Open Sans для тексту) з правильними style-неймами.
4. **Мова** — увесь текстовий контент, який генерується або редагується (заголовки, лейбли, кнопки, плейсхолдери) — завжди англійською мовою, незалежно від мови запиту в чаті.
5. **Внутрішні блоки лейауту** — будуються з компонента `Card/Default` (реальний instance з дизайн-системи), а не з ручних frame + fills.

## 3. Оновлення файлів/правил

Щоразу, коли фіксується щось нове або змінюється `rules.md` (додається/прибирається/коригується правило), одразу після цього створюється оновлений файл `rules.md` і видається користувачу посилання на завантаження — а не просто текстове підтвердження.
